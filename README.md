 # 🇮🇳 SamadhanSetu

 ### AI-Powered Civic Problem Discovery, Collaboration & Resolution Platform

 > **From Citizen Problems → AI Intelligence → Universities → Industry → Solutions → Government Impact**

 SamadhanSetu is a civic-innovation platform that connects **citizens, communities, universities, students, faculty, industries, CSR organizations, and government administrators** around real-world societal problems.

 The platform transforms an unstructured civic problem into a structured innovation workflow:

```
Citizen reports a problem
        ↓
AI analyzes and classifies the problem
        ↓
Duplicate / similar problems are detected
        ↓
Priority and domain are determined
        ↓
Relevant university / department is recommended
        ↓
University evaluates the challenge
        ↓
Faculty + students form a project team
        ↓
Project / milestones / tasks are created
        ↓
Industry / CSR partners can support the project
        ↓
Progress is tracked
        ↓
Government monitors outcomes through dashboards
        ↓
Citizen ultimately benefits from the solution
```

 # 🌍 Overview

 SamadhanSetu is a **GovTech + Civic Innovation + AI + Education collaboration platform**.

 The fundamental idea is simple:

 > Citizens experience problems every day, while universities, students, faculty, industries and governments possess different pieces of the expertise and resources required to solve them.

 SamadhanSetu attempts to connect these disconnected capabilities into one digital ecosystem.

 Instead of treating a citizen complaint as the end of a process, SamadhanSetu treats it as the **beginning of an innovation lifecycle**.

 The platform creates a bridge between:

```
Citizens
```

 # 🎯 Problem Statement

 Communities encounter problems involving:

 - Education
- Agriculture
- Healthcare
- Water resources
- Sanitation
- Environment
- Energy
- Urban infrastructure
- Accessibility
- Public administration
- Rural livelihoods
- Local public services

 Citizens are often the first people to discover these problems.

 However, several challenges exist:

 1. Problems are reported through disconnected channels.
2. Similar problems may be reported repeatedly.
3. Issues are not always categorized consistently.
4. Government departments may not have immediate access to specialized academic expertise.
5. Universities may not know which real-world problems need research.
6. Students may work on projects disconnected from actual community needs.
7. Industry and CSR organizations may have resources but lack structured problem discovery.
8. Government leadership may lack a unified view of ongoing civic innovation projects.
9. There is often no continuous lifecycle from problem identification to deployment.
10. Measuring the social impact of academic projects can be difficult.

 SamadhanSetu addresses this gap by creating a common digital ecosystem.

 ## 🔍 Semantic Duplicate Detection

 Different citizens can describe the same problem in completely different ways.

 For example:

```
Issue A:
"There is no drinking water in our village."

Issue B:
"Our village has not received safe potable water for months."
```

 Keyword matching may fail to identify these as related.

 Semantic embeddings allow the system to compare the meaning of the descriptions.

 # 🧠 AI/ML Pipeline

 The AI functionality is implemented as a standalone **FastAPI microservice**.

 The browser does not directly communicate with Gemini.

 Instead:

```
React
  ↓
Spring Boot
  ↓
AI Bridge
  ↓
FastAPI
  ↓
Gemini / Fallback
  ↓
AI Result
  ↓
Spring Boot
  ↓
Database
  ↓
Frontend
```

 This separation:

 - protects API credentials,
- isolates AI logic,
- simplifies scaling,
- makes AI providers replaceable,
- allows deterministic fallbacks.

---

 ## AI Processing Stages

 ### Stage 1 — Input

 Spring Boot sends:

 - issue ID,
- title,
- description,
- location,
- candidate existing issues.

 ### Stage 2 — Language Handling

 The prototype supports Hindi/English processing paths.

 ### Stage 3 — Summarization

 The system creates a concise representation of the problem.

 ### Stage 4 — Classification

 The issue is assigned to a canonical domain.

 Supported domains include:

```
Education
Agriculture
Healthcare
Water Resources
Environment
Energy
Urban Development
Accessibility
Public Administration
Rural Livelihoods
```

 ### Stage 5 — Priority

 The prototype supports:

```
LOW
MEDIUM
HIGH
CRITICAL
```

 Priority logic is currently primarily rule-based.

 ### Stage 6 — Embedding

 The issue is converted into a semantic embedding.

 ### Stage 7 — Similarity Search

 FAISS compares the embedding against candidate issues.

 ### Stage 8 — Duplicate Detection

 A configurable threshold determines whether the issue may be semantically duplicated.

 ### Stage 9 — Routing

 The resulting domain is mapped to academic routing rules.

 # 🔍 Semantic Duplicate Detection

 The prototype uses:

 - Gemini embeddings
- normalized vectors
- FAISS
- similarity threshold
- optional geographic distance

 The configured prototype threshold is:

```
AI_DUPLICATE_THRESHOLD=0.78
```

 Conceptually:

```
Issue
  ↓
Embedding
  ↓
Normalize
  ↓
FAISS
  ↓
Nearest Candidate
  ↓
Similarity Score
  ↓
Duplicate Decision
```

 A future production system can combine:

```
Semantic similarity
+
Geographic proximity
+
Domain similarity
+
Time proximity
+
Administrative boundary
+
Issue status
+
Evidence similarity
```

 to produce a more robust duplicate confidence score.

 # ⚠️ Known Limitations

 SamadhanSetu is currently a **hackathon/MVP prototype**, not a finished nationwide production system.

 Important limitations include:

 ### AI

 - AI is not a custom-trained civic model.
- Priority is primarily rule-based.
- Classification is prototype-oriented.
- Institutional routing is currently rule-based.
- AI quality depends partly on external model availability.

 ### Infrastructure

 - FAISS is suitable for the current prototype but may need replacement/scaling for very large datasets.
- MySQL is suitable for the current implementation; production GIS requirements may favor PostgreSQL/PostGIS.
- Production deployment requires more comprehensive observability.

 ### GIS

 Current mapping is lightweight.

 Advanced geospatial analysis remains future scope.

 ### Notifications

 The current notification layer is primarily application-level.

 Full:

 - SMS,
- WhatsApp,
- email,
- push

 integrations remain future scope.

 ### Mobile

 A dedicated mobile application is future scope.

 ### Multilingual Support

 The prototype provides Hindi/English processing paths, while broad regional-language support remains future work.
